## 設計 (引き継ぎ書より)

- 縦画面スマホ向け、60 秒スコアアタック
- リング (anchor) を指でドラッグ、伸縮バネのロープで重りがぶら下がる
- 破壊するたびに重りの `mass` と `radius` が増加。重いほど衝撃とスコア効率が上がる
- ロープ張力が高い状態が続くと `ropeIntegrity` が低下し、限界超過で切断 → 終了
- 的は 4 種 (`normal` / `gold` = +3 秒 / `prism` = 高得点 / `drifter` = 移動)
- RUSH MODE: ゲージ 100% で約 7 秒の強化状態 (得点 ×2 / ロープ保護 / BGM 密度アップ)
- ローカルランキング (最大 100 件、上位 10 件表示)
- Web Audio API のリアルタイム合成のみ (外部音源なし)。132 BPM テクノ BGM + 多層の撃破 SE

## なぜこれが効いているか

**ふりこの大冒険で未解決だった切断の裁定を、構造的に解いている。** ふりこ側は「深く伸ばす動機が得点式だけ」で、しかも実測で伸び率 0.66 止まり = 上半分が死んでいた。RUSH 側は張力が高いほど高得点かつ RUSH ゲージが伸びるので、危険を攻める動機が最初から組み込まれている。さらに「破壊 → 重くなる → 衝撃が増える → 張力が危険になる → ギリギリを攻める」の成長ループがあり、60 秒という枠が緊張感を担保している。

## 決めること

1. **ふりこの大冒険との関係** — 畳んで乗り換えるか / 要素だけ移植するか / 別物として並行させるか
2. **対象読者の差** — ふりこは小学生の子ども向け (横画面・ひらがな・文字なし設計)、RUSH は縦画面スマホのアーケード寄りで BGM もテクノ。同じ人向けの製品ではない
3. **repo 化と配信先** — 現状 `~/Downloads` にあるだけ。GitHub Pages に載せるなら公開リポジトリの新設が要る

## 引き継ぎ書が定める不可侵 (引き取る場合に守るもの)

- HUD とプレー領域を重ねない (`getPlayBounds()` を CSS と同時に直す)
- 的は `getTargetBounds()` の届く範囲に出す (「見えている = 届く」ではない)
- AudioContext はユーザー操作後に開始する (iPhone で無音になる)
- localStorage の既存ランキングとの互換を壊さない
- 物理更新は固定 timestep (`fixedDt = 1/120`) を維持
- `restLength * 2.16` の即切断条件を下げすぎない
